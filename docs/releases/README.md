## 쓰는 방법

1. `vX.Y.Z.md` 를 만들고 이전 버전 파일의 구성을 따른다.
2. 머리말에 릴리즈일, 대상 커밋, 이전 버전 링크를 적는다.
3. 이 표에 한 줄 추가한다.
4. 배포하고 실제 동작을 확인한 뒤 태그를 밀고 릴리즈를 올린다.

   ```
   npm run deploy
   git tag vX.Y.Z
   git push origin vX.Y.Z
   gh release create vX.Y.Z --title "vX.Y.Z" --notes-file docs/releases/vX.Y.Z.md --latest
   ```

checky 는 사용자가 버전을 고를 수 없는 호스팅 서비스다.
릴리즈 노트가 먼저 나가면 "이렇게 동작한다"고 알린 내용이 아직 반영되지 않은 상태가 되므로,
**배포와 확인을 마친 뒤 태그를 단다.**

## 구성

섹션은 해당하는 것만 쓴다. 빈 섹션은 남기지 않는다.

- **Overview** — 이번 릴리즈가 무엇을 위한 것인지 한 문단
- **Security** / **Legal** — 보안·법적 고지 변경. 있으면 Features 보다 앞에 둔다
- **Features** — 새로 생긴 것
- **Improvements** — 있던 것이 나아진 것
- **Fixes** — 잘못 동작하던 것
- **Notes** — 이용자가 알아야 할 주의사항
- **Next Plans** — 다음에 할 것

릴리즈 노트 파일은 통째로 공개된다. 배포하는 사람만 알면 되는 사항은 여기 쓰지 말고
[배포 메모](../deployment.md)에 남긴다.

## 버전 규칙

- 깨지는 변경이 있으면 major
- 기능이 늘면 minor
- 수정만 있으면 patch
